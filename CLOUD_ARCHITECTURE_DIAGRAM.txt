═══════════════════════════════════════════════════════════════════════════════
                            KEY FLOWS
═══════════════════════════════════════════════════════════════════════════════

1. INITIALIZATION (Sign In)
   ┌────────────────────────────────────────────────────────────────┐
   │ App.tsx detects auth.isSignedIn()                              │
   │   ↓                                                              │
   │ Calls connectCloudWebSocket()                                   │
   │   ↓                                                              │
   │ Gets Clerk JWT: plugin:clerk|get_client_authorization_header   │
   │   ↓                                                              │
   │ Calls register_cloud_device(device_id, api_origin)             │
   │   ↓                                                              │
   │ Establishes WebSocket to wss://.../api/ws?token={JWT}&...      │
   │   ↓                                                              │
   │ Starts 30-second heartbeat                                      │
   │   ↓                                                              │
   │ Receives Friends/Devices/Tickets updates                        │
   │   ↓                                                              │
   │ Updates CloudPresenceRuntime.snapshot                           │
   │   ↓                                                              │
   │ Emits cloud_*_updated events to Frontend                        │
   └────────────────────────────────────────────────────────────────┘

2. SEND TO FRIEND (HTTP + WebSocket)
   ┌────────────────────────────────────────────────────────────────┐
   │ Friends Page: handleSendToFriend(friend)                       │
   │   ↓                                                              │
   │ Generate ticket: send_file() → invoke("send_file", ...)        │
   │   ↓                                                              │
   │ Call FriendsService.sendTicketToFriend(friendUserId, ticket)   │
   │   ↓                                                              │
   │ HTTP POST /api/tickets with Authorization header               │
   │   ├─ friendUserId (or deviceId)                                │
   │   ├─ ticket (transfer blob)                                    │
   │   └─ filename                                                   │
   │   ↓                                                              │
   │ Cloud backend stores ticket, broadcasts to friend via WS        │
   │   ↓                                                              │
   │ Friend receives "tickets" message on WebSocket                  │
   │   ↓                                                              │
   │ update_cloud_state() in Rust → update_cloud_tickets()          │
   │   ↓                                                              │
   │ Emits cloud_tickets_updated event → Friend notified            │
   └────────────────────────────────────────────────────────────────┘

3. RECONNECTION (Exponential Backoff)
   ┌────────────────────────────────────────────────────────────────┐
   │ WebSocket connection fails / closes                             │
   │   ↓                                                              │
   │ scheduleReconnect() calculates delay:                           │
   │   1000ms × 2^attempt capped at 30s                              │
   │   ↓                                                              │
   │ setTimeout(connectCloudWebSocket, delay)                        │
   │   ↓                                                              │
   │ On success: reset reconnectAttempt to 0                         │
   │   ↓                                                              │
   │ On failure: increment and retry                                 │
   │   ↓                                                              │
   │ Exponential backoff: 1s, 2s, 4s, 8s, 16s, 30s, 30s, ...        │
   └────────────────────────────────────────────────────────────────┘

═══════════════════════════════════════════════════════════════════════════════
                         DATA FLOW SUMMARY
═══════════════════════════════════════════════════════════════════════════════

AUTHENTICATION
  └─ Clerk JWT obtained via tauri-plugin-clerk
     └─ Passed to Cloud API as "Authorization: Bearer {JWT}"
     └─ Passed to WebSocket as "?token={JWT}"

DEVICE IDENTIFICATION
  └─ Persistent UUID stored in localStorage["sendme_device_id"]
     └─ Sent in WebSocket query: "?deviceId={UUID}"
     └─ Sent in X-Device-Id header for ticket endpoints

REAL-TIME STATE
  └─ CloudPresenceRuntime maintains in-memory snapshot
     └─ RwLock<CloudPresenceRuntime> shared across Tauri commands
     └─ Generation counter prevents stale updates
     └─ Events emitted for each state change

HTTP VS WEBSOCKET
  └─ HTTP: Stateless operations (add friend, send ticket, get friends)
  └─ WebSocket: Real-time push updates (friend online, incoming tickets)

ERROR HANDLING
  └─ Heartbeat failure → reconnect
  └─ Device registration failure → delay reconnect
  └─ No auth token → refuse connection
  └─ Server-sent errors → emit cloud_presence_error event
  └─ Generation mismatch → ignore stale messages
